# {{ProductName}}

Unity 6 + URP project built on Larje packages (`com.larje.*`: `com.larje.core` services, `com.larje.ui` screens/popups/toasts and UI animations) with Zenject. The base was generated by `com.larje.projectsetup`. To recreate missing pieces, run `Tools/Larje/Project Setup/Run` again. It is idempotent and keeps existing assets.

## Layout

- `Assets/_Project/Scripts`: project code, assembly `{{Namespace}}` (namespace `{{Namespace}}`).
  - `Installers/ProjectInstaller.cs`: project bindings, added to `ProjectContext` after `LarjeCoreInstaller` and `LarjeUIInstaller`.
  - `Flow/`: game flow controllers (plain C# services).
- `Assets/_Project/Configs`: Larje configs (`SaveConfig`, `UIConfig`, `InputConfig`, `GameStatesConfig`, `AppFlowConfig`, `SoundConfig`, `CurrencyConfig`, ...). Id assets live in `Configs/Ids/<IdType>/`.
- `Assets/_Project/Configs/Installers`: `LarjeCoreInstaller`, `LarjeUIInstaller` (references `UIConfig`) and `ProjectInstaller` assets.
- `Assets/_Project/Resources/ProjectContext.prefab`: the Zenject project context with the installers above.
- `Assets/_Project/UI`: UI Toolkit. `Screens/`, `Popups/`, `Toasts/` hold UXML (+ page USS) exported from the design mockups, `Styles/` holds `tokens.uss`, `kit.uss`, `game.uss`, `assets.uss`, plus `Fonts/`, `Art/`, `LarjePanelSettings.asset` and `LarjeTheme.tss`. These files are generated by `design.py ui-export`: change the mockup (HTML/CSS in the design folder) and re-export instead of editing them; game-specific runtime styling goes into the mockup's `game.css`.
- `Assets/_Project/Scripts/UI/Views`: generated typed views (`<Name>View`, element properties by mockup `data-unity` names) and `UIKeys`. Never edit; re-export.
- `UIMockups/` (project root): mockup layout JSON and screenshots used by `UIMockupTests` (layout parity at the reference resolution).
- `Assets/_Project/Scenes`: `Splash` (build index 0) and `Main`. `AppFlowService` shows the splash, sets the `Menu` state and loads `Main`. `MenuScreenController` opens the main menu screen.
- `Assets/_Project/Settings`: URP asset and `GameInput.inputactions` (Player and UI maps).
- `Assets/_Project/Editor`: editor assembly `{{Namespace}}.Editor`. `Builders/` holds idempotent builder scripts that create or update scenes, prefabs, configs and level data; run them with the `unity-editor` skill (`run_method.py`: in the running editor through the Unity CLI, or in batch mode when no editor is open).
- `Assets/_Project/Tests/PlayMode`: playtests (assembly `{{Namespace}}.Playtests`) built on `Larje.ProjectSetup.Editor.Playtest.PlaytestSession`. `SmokePlaytest` boots from `Splash` to the main menu and takes screenshots.

## Architecture rules

- Services are plain C# classes with constructor injection. Bind them in `ProjectInstaller` with `BindInterfacesTo<T>().AsSingle()`. Implement `IInitializableService`, `IAsyncInitializableService` or `IDisposable` for lifecycle; `LarjeInitializer` calls them.
- Use UniTask with a `CancellationToken` for loops and async work. Do not use `Update` loops or coroutines in services.
- Ids are ScriptableObject assets (`GameStateId`, `UIScreenId`, `SoundId`, `CurrencyId`, ...). Do not use string or enum ids.
- Each feature keeps its persistent data in its own save section.
- Zenject injects scene objects before `Awake`. A `Construct` method must not depend on fields initialised in `Awake`.
- UI: export mockups with `design.py ui-export <design> <project>` (it also syncs ids and `UIConfig` entries through `Larje.UI.Editor.UIViewSync`). Behaviour lives in controllers: `sealed class ShopPopup : UIPopup<ShopPopupView>` (plain C#, constructor injection), wire buttons in `OnViewReady` (`View.BuyButton.clicked += ...`), set mockup states with `States.Set("no_ads", true)`. Register in `ProjectInstaller`: `Container.BindUIController<ShopPopup>(UIKeys.ShopPopup)`. Open with `IUIService.OpenScreen/OpenPopup/ShowToast` (id asset or `UIKeys` key). Animations come from mockup `data-anim` presets (`anim--*` classes); coin flights use `UIFlyEffect`, counters `UICurrencyLabel`.

## Code style (C#)

- No `var`, no comments, no `continue`.
- Seal classes where possible. Use block bodies for methods and `if` statements.
- Make private methods `static` only when required.
- Order members as: constants, static fields, serialized fields, fields, properties, events, methods, nested types. Within each group: public, protected, private.
- Private fields use `_camelCase`. Serialized fields use `[Header]` groups and never `[Tooltip]`.

## Working with the editor

- Change `.unity`, `.prefab`, `.asset` and `.mat` files only through Unity (builder scripts or `unity command` against a running editor), never as text.
- The project has `com.unity.pipeline`, so a running editor (the user's GUI editor, or a headless one started with the `unity-editor` skill: `editor.py up`) is driven with the Unity CLI. Pass `--project-path <project>` to every call.
- After every C# change run `unity recompile --project-path <project>` (seconds; prints compile errors, exit 6 on errors), then check `unity command console get --project-path <project> -- --level error`. Without a running editor use `compile.py` from the `unity-editor` skill.
- Useful built-in commands: `unity command script eval '<C#>'`, `unity command scene get_hierarchy`, `unity command scene save`, `unity command editor status`. `unity command` lists the groups, `unity command <group>` their commands.
- Larje commands: `unity command larje validate` (config problems), `larje.configs list`, `larje.ids list` / `larje.ids create`, `larje.save read` / `larje.save write`, `larje.debug list` / `larje.debug run` (Play Mode). `unity command larje` lists them with their parameters.

## Playtests and builds

- Playtests are PlayMode tests: `PlaytestSession` loads scenes, waits, clicks buttons by name or label, drives virtual keyboard/mouse/touch (`session.Input`), takes screenshots (`yield return session.CaptureAsync("label")`: cameras plus UI Toolkit panels) and writes `Logs/Playtest/<name>/report.txt` with steps, errors and frame times. Add a playtest for every new game flow and look at the screenshots.
- Run them with the `unity-playtest` skill (in the running editor through the Unity CLI, or `unity test` in batch mode when no editor is open) or the Test Runner window.
- Build with the `unity-build` skill or `Larje.ProjectSetup.Editor.Build.ProjectBuildRunner.RunFromCommandLine` (`-larjeBuildTarget Android|WebGL|StandaloneLinux64`, `-larjeBuildAab`, `-larjeBuildDevelopment`, `-larjeBuildVersion`, `-larjeBuildNumber`, `-larjeWebGLTemplate LarjeTelegram`, `-larjeKeystore` + `-larjeKeyAlias` with `LARJE_KEYSTORE_PASS` / `LARJE_KEY_PASS`). The report is written to `Logs/LarjeBuild.txt`.
