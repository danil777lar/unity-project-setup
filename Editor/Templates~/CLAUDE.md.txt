# {{ProductName}}

Unity 6 + URP project built on Larje packages (`com.larje.*`) with Zenject. The base was generated by `com.larje.projectsetup`. To recreate missing pieces, run `Tools/Larje/Project Setup/Run` again. It is idempotent and keeps existing assets.

## Layout

- `Assets/_Project/Scripts`: project code, assembly `{{Namespace}}` (namespace `{{Namespace}}`).
  - `Installers/ProjectInstaller.cs`: project bindings, added to `ProjectContext` after `LarjeCoreInstaller`.
  - `Flow/`: game flow controllers (plain C# services).
- `Assets/_Project/Configs`: Larje configs (`SaveConfig`, `UIConfig`, `InputConfig`, `GameStatesConfig`, `AppFlowConfig`, `SoundConfig`, `CurrencyConfig`, ...). Id assets live in `Configs/Ids/<IdType>/`.
- `Assets/_Project/Configs/Installers`: `LarjeCoreInstaller` and `ProjectInstaller` assets.
- `Assets/_Project/Resources/ProjectContext.prefab`: the Zenject project context with the installers above.
- `Assets/_Project/Prefabs/UI`: UI screens (`UIScreen` + `UIScreenId`), listed in `UIConfig`.
- `Assets/_Project/Scenes`: `Splash` (build index 0) and `Main`. `AppFlowService` shows the splash, sets the `Menu` state and loads `Main`. `MenuScreenController` opens the main menu screen.
- `Assets/_Project/Settings`: URP asset and `GameInput.inputactions` (Player and UI maps).
- `Assets/_Project/Editor`: editor assembly `{{Namespace}}.Editor`. `Builders/` holds idempotent builder scripts that create or update scenes, prefabs, configs and level data; run them in batch mode with the `unity-editor` skill (`run_method.py`).
- `Assets/_Project/Tests/PlayMode`: playtests (assembly `{{Namespace}}.Playtests`) built on `Larje.ProjectSetup.Editor.Playtest.PlaytestSession`. `SmokePlaytest` boots from `Splash` to the main menu and takes screenshots.

## Architecture rules

- Services are plain C# classes with constructor injection. Bind them in `ProjectInstaller` with `BindInterfacesTo<T>().AsSingle()`. Implement `IInitializableService`, `IAsyncInitializableService` or `IDisposable` for lifecycle; `LarjeInitializer` calls them.
- Use UniTask with a `CancellationToken` for loops and async work. Do not use `Update` loops or coroutines in services.
- Ids are ScriptableObject assets (`GameStateId`, `UIScreenId`, `SoundId`, `CurrencyId`, ...). Do not use string or enum ids.
- Each feature keeps its persistent data in its own save section.
- Zenject injects scene objects before `Awake`. A `Construct` method must not depend on fields initialised in `Awake`.
- To open UI, add a `UIScreen` / `UIPopup` prefab, create its id, list it in `UIConfig`, then call `IUIService.OpenScreen` / `OpenPopup`.

## Code style (C#)

- No `var`, no comments, no `continue`.
- Seal classes where possible. Use block bodies for methods and `if` statements.
- Make private methods `static` only when required.
- Order members as: constants, static fields, serialized fields, fields, properties, events, methods, nested types. Within each group: public, protected, private.
- Private fields use `_camelCase`. Serialized fields use `[Header]` groups and never `[Tooltip]`.

## Working with the editor

- Change `.unity`, `.prefab`, `.asset` and `.mat` files only through Unity (MCP tools or editor scripts), never as text.
- After every C# change, refresh, wait until compilation is idle, and check that the console has no errors.
- Unity AI MCP tools: `Larje.ValidateProject` (config problems), `Larje.ListConfigs`, `Larje.ListIds` / `Larje.CreateId`, `Larje.ReadSave` / `Larje.WriteSaveSection`, `Larje.ListDebugCommands` / `Larje.RunDebugCommand` (Play Mode).

## Playtests and builds

- Playtests are PlayMode tests: `PlaytestSession` loads scenes, waits, clicks buttons by name or label, drives virtual keyboard/mouse/touch (`session.Input`), takes screenshots (cameras and overlay UI) and writes `Logs/Playtest/<name>/report.txt` with steps, errors and frame times. Add a playtest for every new game flow and look at the screenshots.
- Run them with the `unity-playtest` skill (batch mode, editor closed) or the Test Runner window.
- Build with the `unity-build` skill or `Larje.ProjectSetup.Editor.Build.ProjectBuildRunner.RunFromCommandLine` (`-larjeBuildTarget Android|WebGL|StandaloneLinux64`, `-larjeBuildAab`, `-larjeBuildDevelopment`, `-larjeBuildVersion`, `-larjeBuildNumber`, `-larjeWebGLTemplate LarjeTelegram`, `-larjeKeystore` + `-larjeKeyAlias` with `LARJE_KEYSTORE_PASS` / `LARJE_KEY_PASS`). The report is written to `Logs/LarjeBuild.txt`.
